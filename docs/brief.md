# Hackathon Brief — Your Move
## UX AI Hackathon. Intent → Action

---

## Context

Every day, people intend to do something:
- start exercising
- organize their tasks
- send an important message
- spend their time more meaningfully

But in reality, intention rarely turns into action.

Common reasons: procrastination, choice overload, unclear first step, fear or low motivation, lack of structure.

This is not a "discipline problem." It is a **UX problem of transitioning from intent to action.**

---

## Challenge

Design a digital product (or service) that helps a user **move from intention to a concrete action in the moment.**

Not just reminding. Not just motivating. But actually helping the user **start and continue.**

---

## Possible Directions (not limiting)

- "I want to start running" → first run
- "I need to organize my tasks" → actually starting
- "I should text someone" → sending the message
- "I want a better weekend" → making a decision and acting

Focus on behavioral UX, not a specific industry.

---

## Constraints

### Tools (AI-only)
Prototyping: Figma Make, Cursor, Claude Code, OpenAI Codex, Lovable, v0, Bolt.new
Research & prompting: ChatGPT, Perplexity, Claude, Grok
Visuals: Midjourney, Nano Banana, OpenAI Images

Provided by organizers: Figma Make (3000 tokens/participant). Everything else — personal accounts.

### Iterative process (core rule)
Evaluated not only on final outcome but on **how the solution evolves.**

For every meaningful iteration, document:
- what changed
- why the change was made
- what problem or insight it addressed

Each iteration must include screenshots + change log with reasoning. Before/after comparisons encouraged.

Corridor testing allowed at any point — document findings and incorporate into iterations.

### Team & Time
One working week including weekend. Teams of 2.

### Technical Restrictions
- Shared component library: Material UI (or choice)
- Shared icon library: DataArt Figma icon set (colors adjustable)

3. User Flow

---

## Evaluation Criteria

1. UX solution
2. Iterative process
3. Visual quality
4. Final prototype
5. Project presentation

---

## What to Avoid

- Generic "to-do list with AI" solutions
- Solutions that don't focus on the first action
- Overly complex interfaces
- Trying to solve too many scenarios

---

## Guiding Question

**Why hasn't the user acted yet — and how does your solution change that?**
