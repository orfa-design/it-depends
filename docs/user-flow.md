# User Flow — It Depends

**JTBD:** Коли я бачу що колеги роблять з AI щось реальне → я хочу зробити перший крок від слів до живого результату → щоб перестати відчувати що це не для мене.

**Версія:** v2 (2026-05-26) — story-driven calibration

> ⚠️ Попередній флоу (v1) більше не актуальний. Описи екранів v1 залишені нижче для архіву.

---

## Флоу v2

```
Головна → /calibrate → /calibrate/[1-4] → /next-step → /prompt → /done
                                                ↑
                                        [AI-path — гіпотеза]
```

**Платформа:** desktop (не мобайл).

---

### Блок 1 — Калібрація (`/calibrate` → `/calibrate/[1-4]`)

**Логіка:** Замість прямих питань "який твій рівень?" — продукт показує реальні кейси дизайнерок і зчитує реакцію. Це вирішує H5 (capability blindness): юзер бачить що AI може конкретно, а не відповідає абстрактно.

- `/calibrate` — вступний екран, пояснює формат (story cards)
- `/calibrate/[1-4]` — 3–4 картки з реальними кейсами; юзер обирає реакцію:
  - "Фантастика" — не знала що так можна
  - "Чула, не пробувала" — бачила, але не дійшли руки
  - "Вже роблю" — знайоме

**Чому це краще за v1:** Питання "який рівень?" вимагає від юзера самооцінки — і вона занижена (H2). Реакція на конкретний кейс — точніша і не лякає.

**Що зберігається:** Патерн реакцій → визначає рівень і тип рекомендації на наступному екрані.

---

### Блок 2 — Рекомендація (`/next-step`) — розвилка, рішення не прийнято

Продукт визначає один конкретний наступний крок на основі калібрації. **Два конкуруючих підходи:**

**Варіант A — Тіндер (свайп):**
Одна картка за раз. Юзер свайпає — відхиляє або бере. Простий вибір без аналізу.

**Варіант B — Галерея під больові точки:**
Набір рішень організованих навколо конкретних болів дизайнера ("автоматизувати назви компонентів", "генерувати стани елементів"). Кожне рішення = промпт + інструкція + рекомендований інструмент. Показує *як* інтегрувати AI в реальний робочий процес — не абстрактно.

*Різниця:* A — вибираєш задачу. B — впізнаєш свій біль і бачиш готове рішення. B краще закриває H4 (latent ideas), A — простіша в реалізації.

**Escape hatch:** якщо нічого не підходить → юзер описує своє завдання своїми словами.

---

### Гіпотетична гілка — AI-generated path

Якщо юзер не впізнає себе в жодній картці → вводить свій біль вільним текстом → продукт перетворює це (через AI) на структурований промпт з інструкцією.

Закриває H4/H5 для юзерів з latent ideas: замість вибору з готового — вона описує рутину, продукт переводить у "buildable project."

*Відкрите питання:* окрема гілка чи доступна як escape hatch з будь-якого місця?

---

### Блок 3 — Промпт (`/prompt`)

**Що бачить юзер:** готовий промпт + покрокова інструкція + рекомендований інструмент.

- Для Claude задач: кнопка "Скопіювати" + "Відкрити в Claude →"
- Для Claude Code задач: кнопка "Скопіювати" + інструкція для терміналу
- Кнопка "Я спробувала ✓" після виконання

**Completion state:** "Ти вже не та що збиралася — ти та що зробила" + кнопка "Поділитись" + "Зробити ще один крок →"

---

### Блок 4 — Done (`/done`)

Achievement картка (Strava-style): назва кроку, інструмент, кнопка "Поділитись", кнопка повернення.

**Роль share:** Acquisition loop — колега бачить пост → приходить у продукт. Але для самої юзерки це не retention (підтверджено інтерв'ю з Крістиною).

---

### ⚠️ Відкритий UX gap — Retention

**Проблема:** Юзер пішла виконувати проєкт з AI-тулом. Чому вона повернеться?

Соціальний share закриває acquisition, але не retention. Крістина повертається коли з'являється нова конкретна задача — не від нотифікацій чи лайків.

**Гіпотези що обговорювались (статус: ідеї, не рішення):**
- Маскот (Duolingo-style) — механіка повернення через персонажа
- Обмежені токени — організовує поведінку, але потребує причини повернутись
- Розбивка на підзадачі — незакінчена задача як pull до повернення
- Task-triggered return — повертається сама коли з'являється нова задача

*Потрібно перевірити на наступних інтерв'ю: що конкретно виглядало б як причина повернутись через тиждень?*

## Флоу v1 (архів)

```
Головна → /start → /start/pain → /start/access → /start/steps → /start/suggest → /done
```

---

## Екран 1 — Вибір рівня (`/start`)

**Що бачить юзер:** Три варіанти що описують поточний рівень роботи з AI.
- Спілкуюсь з Claude — базовий чат, підсумки, запити
- Аналізую з Claude — документи, транскрипти, дослідження
- Будую з Claude — плагіни, скрипти, автоматизація

**Що робить:** Вибирає один варіант → одразу переходить далі.

**Навіщо цей крок:** Персоналізація — рівень визначає тип артефакту і інструмент на виході (Claude або Claude Code).

---

## Екран 2 — Мотивація (`/start/pain`)

**Що бачить юзер:** Чотири варіанти навіщо вона тут.
- Автоматизувати щось рутинне
- Побудувати свій інструмент
- Надихнулась чимось — хочу спробувати схоже
- Покажи що взагалі можна зробити

**Що робить:** Вибирає один варіант → 300мс анімація → переходить далі.

**Навіщо цей крок:** Разом з рівнем визначає яку карточку показати першою. 12 комбінацій (3 рівні × 4 мотивації).

---

## Екран 3 — Інструменти (`/start/access`)

**Що бачить юзер:** Список інструментів — вибирає все що є.
- Claude.ai Free / Claude Pro / Claude Code
- Lovable / Figma Make / Cursor

**Що робить:** Мульти-селект → "Далі →" з'являється після першого вибору. Зберігає в `localStorage`.

**Навіщо цей крок:** Ранжування карточок — сумісні з її інструментами з'являються першими. Claude Code задачі не пропонуються якщо вона не має Claude Code.

---

## Екран 4 — Пропозиція (`/start/steps`)

**Що бачить юзер:** Одна головна карточка "Підібрано для тебе" + 2 альтернативи внизу.

Кожна карточка:
- Бейдж: Claude або Claude Code
- Назва задачі
- Що отримає на виході (артефакт)
- Кнопка "Спробую це →"

**Що робить:** Натискає "Спробую це →" → переходить на промпт. Або натискає альтернативу.

**Навіщо цей крок:** Вирішує проблему "не знаю що зробити" — продукт сам підбирає і пропонує конкретний перший крок.

---

## Екран 5 — Промпт (`/start/suggest`)

**Що бачить юзер:** Готовий промпт під її задачу + кнопка дії.

Для **Claude задач:**
- Кнопка "Скопіювати промпт"
- Кнопка "Відкрити в Claude →" (відкриває claude.ai)

Для **Claude Code задач:**
- Кнопка "Скопіювати промпт"
- Після копіювання: покрокова інструкція як запустити в терміналі (`claude` команда)

Нижче: роздільник → кнопка "Я спробувала ✓"

**Completion state** (після "Я спробувала"):
- Текст: "Ти вже не та що збиралася — ти та що зробила"
- Кнопка "Поділитись" (Web Share API або копіює посилання)
- Кнопка "Зробити ще один крок →"

**Навіщо цей крок:** Закриває gap між наміром і дією — промпт готовий, залишається тільки вставити.

---

## Екран 6 — Completion (`/done`)

**Що бачить юзер:** Achievement картка (Strava-style).
- Назва виконаного кроку
- Інструмент який використала
- Кнопка "Поділитись"
- Кнопка повернення

**Навіщо цей крок:** Момент святкування і identity shift — "я та що зробила". Соціальний share як потенційний acquisition loop для нових юзерів.

---

## Що зберігається в localStorage

```json
{
  "itdepends_profile": {
    "level": "chat | analyze | build",
    "access": ["claude", "claude-pro", "claude-code", ...]
  }
}
```

Використовується для повернення — юзер не проходить онбординг повторно.

---

## Відкриті питання (після інтерв'ю з Крістиною, 2026-05-26)

- **Pain screen** потребує рефрейму: "що хочеш зробити?" не працює для юзерів з H4 (latent ideas). Розглянути: показувати категорії болів замість абстрактних мотивацій.
- **Retention механіка:** соціальний share — acquisition loop, але не достатньо для повернення. Треба додаткову механіку.
- **Escape hatch:** якщо жодна карточка не підходить → перехід до повного шляху (Duolingo-style).
- **Артефакт рівня "будую":** картка + промпт задокументовані в liuda.md (2026-05-26). Рівні "аналізую" і "спілкуюсь" — в роботі.
