# User Flow — It Depends

**JTBD:** Коли я бачу що колеги роблять з AI щось реальне → я хочу зробити перший крок від слів до живого результату → щоб перестати відчувати що це не для мене.

**Версія:** v2 (2026-05-26) — story-driven calibration

> ⚠️ Попередній флоу (v1) більше не актуальний. Описи екранів v1 залишені нижче для архіву.

---

## Флоу v2

```
Головна → /calibrate → /calibrate/[1-4] → /next-step → /prompt
```

Детальний опис екранів — в роботі.

**Логіка:**
- `/calibrate` — вступний екран, пояснює формат (story cards)
- `/calibrate/[1-4]` — 3–4 картки з реальними кейсами дизайнерок; юзер обирає реакцію ("Фантастика" / "Чула, не пробувала" / "Вже роблю")
- `/next-step` — продукт на основі реакцій визначає рівень і показує один конкретний наступний крок
- `/prompt` — готовий промпт до дії

**Платформа:** desktop (не мобайл).

## Екран 1 — Вибір рівня (`/start`)

**Що бачить юзер:** Три варіанти що описують поточний рівень роботи з AI.
- Спілкуюсь з Claude — базовий чат, підсумки, запити
- Аналізую з Claude — документи, транскрипти, дослідження
- Будую з Claude — плагіни, скрипти, автоматизація

**Що робить:** Вибирає один варіант → одразу переходить далі.

**Навіщо цей крок:** Персоналізація — рівень визначає тип артефакту і інструмент на виході (Claude або Claude Code).

---

## Екран 2 — Мотивація (`/start/pain`)

**Що бачить юзер:** Чотири варіанти навіщо вона тут.
- Автоматизувати щось рутинне
- Побудувати свій інструмент
- Надихнулась чимось — хочу спробувати схоже
- Покажи що взагалі можна зробити

**Що робить:** Вибирає один варіант → 300мс анімація → переходить далі.

**Навіщо цей крок:** Разом з рівнем визначає яку карточку показати першою. 12 комбінацій (3 рівні × 4 мотивації).

---

## Екран 3 — Інструменти (`/start/access`)

**Що бачить юзер:** Список інструментів — вибирає все що є.
- Claude.ai Free / Claude Pro / Claude Code
- Lovable / Figma Make / Cursor

**Що робить:** Мульти-селект → "Далі →" з'являється після першого вибору. Зберігає в `localStorage`.

**Навіщо цей крок:** Ранжування карточок — сумісні з її інструментами з'являються першими. Claude Code задачі не пропонуються якщо вона не має Claude Code.

---

## Екран 4 — Пропозиція (`/start/steps`)

**Що бачить юзер:** Одна головна карточка "Підібрано для тебе" + 2 альтернативи внизу.

Кожна карточка:
- Бейдж: Claude або Claude Code
- Назва задачі
- Що отримає на виході (артефакт)
- Кнопка "Спробую це →"

**Що робить:** Натискає "Спробую це →" → переходить на промпт. Або натискає альтернативу.

**Навіщо цей крок:** Вирішує проблему "не знаю що зробити" — продукт сам підбирає і пропонує конкретний перший крок.

---

## Екран 5 — Промпт (`/start/suggest`)

**Що бачить юзер:** Готовий промпт під її задачу + кнопка дії.

Для **Claude задач:**
- Кнопка "Скопіювати промпт"
- Кнопка "Відкрити в Claude →" (відкриває claude.ai)

Для **Claude Code задач:**
- Кнопка "Скопіювати промпт"
- Після копіювання: покрокова інструкція як запустити в терміналі (`claude` команда)

Нижче: роздільник → кнопка "Я спробувала ✓"

**Completion state** (після "Я спробувала"):
- Текст: "Ти вже не та що збиралася — ти та що зробила"
- Кнопка "Поділитись" (Web Share API або копіює посилання)
- Кнопка "Зробити ще один крок →"

**Навіщо цей крок:** Закриває gap між наміром і дією — промпт готовий, залишається тільки вставити.

---

## Екран 6 — Completion (`/done`)

**Що бачить юзер:** Achievement картка (Strava-style).
- Назва виконаного кроку
- Інструмент який використала
- Кнопка "Поділитись"
- Кнопка повернення

**Навіщо цей крок:** Момент святкування і identity shift — "я та що зробила". Соціальний share як потенційний acquisition loop для нових юзерів.

---

## Що зберігається в localStorage

```json
{
  "itdepends_profile": {
    "level": "chat | analyze | build",
    "access": ["claude", "claude-pro", "claude-code", ...]
  }
}
```

Використовується для повернення — юзер не проходить онбординг повторно.

---

## Відкриті питання (після інтерв'ю з Крістиною, 2026-05-26)

- **Pain screen** потребує рефрейму: "що хочеш зробити?" не працює для юзерів з H4 (latent ideas). Розглянути: показувати категорії болів замість абстрактних мотивацій.
- **Retention механіка:** соціальний share — acquisition loop, але не достатньо для повернення. Треба додаткову механіку.
- **Escape hatch:** якщо жодна карточка не підходить → перехід до повного шляху (Duolingo-style).
