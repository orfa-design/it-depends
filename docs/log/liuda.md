## 2026-05-24 — Налаштування системи документації і тригерів

**Що робила:**
Розібралась як зробити так щоб Claude і мій і Влада допомагали керувати фіксацією прогресу. Виявилось що правила в CLAUDE.md не гарантують що Claude їх дотримується — особливо в довгій розмові. Пройшли через кілька ітерацій: від "автоматично пиши" до "питай після пушу" до "показуй драфт перед записом".

**Чому саме так:**
Автоматика без контролю давала неточні записи — Claude сам вирішував що "значимо" і помилявся. Вирішили що надійніше коли я ініціюю запис явно, а Claude показує драфт на погодження перед тим як щось писати у файл.

**Що вийшло:**
Окремі файли `docs/log/liuda.md` і `docs/log/vlad.md` для детальних ітераційних записів. Правило в CLAUDE.md з чітким форматом, прикладами поганого і хорошого запису, і вимогою показувати драфт перед записом.

**Що здивувало:**
CLAUDE.md — це більше про наміри ніж гарантії. Claude читає правила але в довгій розмові "забуває" їх застосовувати. Конкретні тригери ("після пушу") надійніші ніж розмиті ("після значимих дій").

**Наступний крок:**
GitHub Action для `docs/status.md` — щоб обидва Claude бачили пуші одне одного.

## 2026-05-24 — Налаштування AI workflow + хуки для командної синхронізації

**Що робила:**
Хотіла залити reference файли для скіла ux-decision-partner — 5 вправ для UX фасилітації.
Виявилось що сам скіл вже встановлений глобально (anthropic-skills:), але файли вправ
не потрапили при інсталяції. Розбирались де їх зберігати — в проекті чи глобально.
Паралельно виявила що Claude ігнорує інструкції з CLAUDE.md: не робив git fetch на початку,
не питав про git pull перед записом в docs/, не оновлював changelog після пушу.
Вирішила закрити це хуками замість поведінкових правил.

**Чому саме так:**
Поведінкові інструкції в CLAUDE.md ненадійні — Claude "забуває" їх в довгих розмовах.
Хуки гарантують виконання незалежно від контексту. Обрала docs/ux-exercises/ для вправ
(не глобально) — щоб вправи були частиною проекту і не тригерились автоматично,
поки не перевіримо скіл в дії.

**Що вийшло:**
- docs/ux-exercises/ з 5 файлами вправ (user snapshot, JTBD, competitor map, hypotheses, scope tree)
- .claude/settings.json з двома хуками: UserPromptSubmit (git fetch — алертить якщо тімейт пушив)
  і PostToolUse (нагадування після git push оновити changelog)
- Хуки в спільному settings.json → Влад отримає після git pull

**Що здивувало:**
Claude сам визнав що не виконував правила CLAUDE.md. Це показало що архітектура
"правило в тексті" vs "хук в коді" — принципово різні речі по надійності.
Поведінкові інструкції — про наміри, хуки — про гарантії.

**Наступний крок:**
Інтерв'ю з колегами-дизайнерами — гіпотези досі не підтверджені, а дедлайн 2 червня.

## 2026-05-24 — Pivot: переосмислення user moment через sounding session

**Що робила:**
Запустила ux-decision-partner скіл в compass mode щоб визначити наступний крок.
Замість того щоб іти в JTBD одразу — зупинилась на питанні чи взагалі
правильний наш user moment. Виявилось що ні.

**Чому саме так:**
Старий snapshot описував момент "відкрив інструмент → злякався → закрив."
Але я засумнівалась — а чи дизайнер взагалі знає що відкривати?
Через кілька питань прийшли до іншого моменту: соціальний тригер
(бачить колегу Влада що вайткодив щось живе) → розуміє що AI це цілий
всесвіт (агенти, GitHub, бази даних) → paralysis ще до відкриття
будь-чого. Wow момент для дизайнера = не "розібратись з інструментом",
а "реалізувати свою маленьку ідею і побачити що вона живе."

**Що вийшло:**
- Повністю переписаний user-snapshot.md з правильним тригером і моментом
- Новий запис в DECISIONS.md з обґрунтуванням pivot'у
- Новий product concept: ми entry point — відповідь на "з чого починати
  з AI взагалі", а не допоміжний інструмент до існуючих AI tools

**Що здивувало:**
Питання "чим це відрізняється від просто відкрити Claude?" виявилось
ключовим. Відповідь: можливо, нічим — і це і є наше позиціонування.
Ми не конкуруємо з Claude, ми те що відкривають ДО нього.

**Наступний крок:**
Інтерв'ю з реальною Оксаною — перевірити чи соціальний тригер
і wow момент резонують. Питання для інтерв'ю треба переписати,
старі вже не відповідають новому розумінню.
