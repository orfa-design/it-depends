## 2026-05-26 — Pivot: від онбордингу до story-driven calibration

**Що робила:**
Відмовились від wizard-онбордингу (6 екранів: level picker → motivation → tools → task card → prompt). Структура не відгукувалась — відчувалась як навчальна платформа і нічим не відрізнялась від звичайного чату з додатковими кліками.

**Чому саме так:**
Ключовий інсайт: юзер не може назвати свій рівень, але може реагувати на конкретне. Питання про рівень = анкета. Реакція на кейс = природна відповідь. Тому переходимо на story cards з адаптивною калібрацією:
- Показуємо реальний кейс дизайнерки (ім'я, біль, що зробила з AI, скільки часу)
- Юзер реагує: "Фантастика" / "Чула, не пробувала" / "Вже роблю"
- 3–4 картки → продукт знає рівень без прямого питання
- На виході: один конкретний наступний крок + готовий промпт

**Що вийшло:**
Зафіксований новий напрямок і флоу: Головна → /calibrate → /calibrate/[1-4] → /next-step → /prompt. Попередній онбординг (feat/onboarding-redesign) задеплоєний як проміжна версія.

**Що здивувало:**
Пройшовши всі ітерації wizard-онбордингу — від простого до складного — прийшли до висновку що проблема була в самій парадигмі, а не в деталях реалізації. Story-driven підхід міняє не дизайн екранів, а модель взаємодії.

**Наступний крок:**
Побудувати /calibrate flow зі story cards. Платформа — desktop.

## 2026-05-24 — Ревізія гіпотез через "звідки знаю" тест

**Що робила:**
Проаналізувала гіпотези через скіл ux-decision-partner. Виявилось що H1/H2 описують paralysis всередині конкретного інструменту — але після pivot'у user moment paralysis відбувається до відкриття будь-чого. Гіпотези описували не той рівень проблеми.

**Чому саме так:**
Пройшла "звідки знаю" тест: кожне твердження перевірила на категорію (known / inferred / hypothesis / wish). Жодна стара гіпотеза не мала реальних доказів, і всі були на рівні "інструмент складний" — що вже суперечило новому розумінню продукту. Паралельно перевірила скільки гіпотез брати в роботу — зупинились на двох критичних (H2 і H4) плюс одній через прототип (H3).

**Що вийшло:**
Три нові гіпотези: H2 (paralysis meta-level, до будь-якого тулу), H4 (дизайнер має work-adjacent ідею зі своєї роботи), H3 (wow момент — своя ідея жива в браузері, тест через прототип). Старі гіпотези в архіві з поясненням. DECISIONS.md і changelog оновлені.

**Що здивувало:**
Можна мати "правильні" гіпотези по формату але не по рівню. Стара H2 "one next step" — правильна ідея, але крок всередині інструменту, а не вхід в AI як явище. Одне слово різниці — інший продукт.

**Наступний крок:**
Інтерв'ю з 2-3 дизайнерами для перевірки H2 і H4. Питання для опитувальника — окремо, під нові гіпотези.

Survey v3 задеплоєний: it-depends.vercel.app/survey

це було AI-генероване припущення, не реальні дані. Показово: навіть в

## 2026-05-24 — Налагодження PostToolUse хука

**Що робила:**
Виявила що PostToolUse хук з matcher `Bash(git push*)` не спрацьовував у Влада після git push через чат. Розібрались що matcher синтаксис міг бути неправильним. Змінили підхід: matcher `"Bash"` + перевірка stdin JSON на наявність `git push` або `git commit`.

**Що вийшло:**
`.claude/settings.json` з оновленим PostToolUse хуком — спрацьовує після `git commit` і `git push`.

**Наступний крок:**
Перевірити що хук реально спрацьовує у Влада після його git pull.

## 2026-05-24 — Опитувальник: від нуля до v2

## 2026-05-25 — Побудова прототипу і повернення до плану

**Що робила:**
Почала будувати інтерактивний прототип продукту в коді — перший екран, потім задачі, потім промпти. В процесі збудила без плану і дрейфанула: замість оригінального флоу (рівень → біль → доступ → свайп-пропозиції) вийшов скорочений (рівень → вибір з меню). Впіймала це під час sounding сесії — повернулась до плану і добудувала правильний флоу.

**Чому саме так:**
Будувала "від руки" без постійної звірки з брейнштормом. Відхилення виявила коли зрозуміла що вихід відчувається як меню а не персоналізована пропозиція — core value prop загубився. Також по дорозі спробувала переформатувати задачі як "artifact-first" (плагін, скрипт, шаблон) — це залишилось, бо відповідає ідеї "виходиш з чимось реальним".

**Що вийшло:**
Робочий прототип флоу: `/start` → `/start/pain` → `/start/access` → `/start/steps` (свайп-картки) → `/start/suggest` (готовий промпт + "Я спробувала" + completion state). Прогрес-крапки на кожному екрані. 9 готових промптів без плейсхолдерів під різні комбінації рівень × задача.

**Що здивувало:**
Дрейф відбувся непомітно — кожен окремий крок здавався логічним, але в сумі вийшло інше. Добре що є план з яким можна звіритись. Також: "Не моє — покажи інше" на екрані з картками — простіша і чесніша механіка ніж swipe-жести, і для вайрфрейму достатньо.

**Наступний крок:**
Задеплоїти на Vercel. Потім — живий артефакт з унікальним URL після "Я спробувала".
