## 2026-05-24 — Ревізія гіпотез через "звідки знаю" тест

**Що робила:**
Проаналізувала гіпотези через скіл ux-decision-partner. Виявилось що H1/H2 описують paralysis всередині конкретного інструменту — але після pivot'у user moment paralysis відбувається до відкриття будь-чого. Гіпотези описували не той рівень проблеми.

**Чому саме так:**
Пройшла "звідки знаю" тест: кожне твердження перевірила на категорію (known / inferred / hypothesis / wish). Жодна стара гіпотеза не мала реальних доказів, і всі були на рівні "інструмент складний" — що вже суперечило новому розумінню продукту. Паралельно перевірила скільки гіпотез брати в роботу — зупинились на двох критичних (H2 і H4) плюс одній через прототип (H3).

**Що вийшло:**
Три нові гіпотези: H2 (paralysis meta-level, до будь-якого тулу), H4 (дизайнер має work-adjacent ідею зі своєї роботи), H3 (wow момент — своя ідея жива в браузері, тест через прототип). Старі гіпотези в архіві з поясненням. DECISIONS.md і changelog оновлені.

**Що здивувало:**
Можна мати "правильні" гіпотези по формату але не по рівню. Стара H2 "one next step" — правильна ідея, але крок всередині інструменту, а не вхід в AI як явище. Одне слово різниці — інший продукт.

**Наступний крок:**
Інтерв'ю з 2-3 дизайнерами для перевірки H2 і H4. Питання для опитувальника — окремо, під нові гіпотези.

## 2026-05-24 — Pivot: переосмислення user moment через sounding session

**Що робила:**
Запустила ux-decision-partner скіл в compass mode щоб визначити наступний крок.
Замість того щоб іти в JTBD одразу — зупинилась на питанні чи взагалі
правильний наш user moment. Виявилось що ні.

**Чому саме так:**
Старий snapshot описував момент "відкрив інструмент → злякався → закрив."
Але я засумнівалась — а чи дизайнер взагалі знає що відкривати?
Через кілька питань прийшли до іншого моменту: соціальний тригер
(бачить колегу Влада що вайткодив щось живе) → розуміє що AI це цілий
всесвіт (агенти, GitHub, бази даних) → paralysis ще до відкриття
будь-чого. Wow момент для дизайнера = не "розібратись з інструментом",
а "реалізувати свою маленьку ідею і побачити що вона живе."

**Що вийшло:**
- Повністю переписаний user-snapshot.md з правильним тригером і моментом
- Новий запис в DECISIONS.md з обґрунтуванням pivot'у
- Новий product concept: ми entry point — відповідь на "з чого починати
  з AI взагалі", а не допоміжний інструмент до існуючих AI tools

**Що здивувало:**
Питання "чим це відрізняється від просто відкрити Claude?" виявилось
ключовим. Відповідь: можливо, нічим — і це і є наше позиціонування.
Ми не конкуруємо з Claude, ми те що відкривають ДО нього.

**Наступний крок:**
Інтерв'ю з реальною Оксаною — перевірити чи соціальний тригер
і wow момент резонують. Питання для інтерв'ю треба переписати,
старі вже не відповідають новому розумінню.

## 2026-05-24 — Налагодження PostToolUse хука

**Що робила:**
Виявила що PostToolUse хук з matcher `Bash(git push*)` не спрацьовував у Влада після git push через чат. Розібрались що matcher синтаксис міг бути неправильним. Змінили підхід: matcher `"Bash"` + перевірка stdin JSON на наявність `git push` або `git commit`.

**Чому саме так:**
`Bash(git push*)` — непідтверджений синтаксис. `"Bash"` з grep по stdin надійніший бо Claude Code передає дані хуку через stdin. Додали тригер і після `git commit` — щоб нагадування з'являлось раніше, не тільки після пушу.

**Що вийшло:**
`.claude/settings.json` з оновленим PostToolUse хуком — спрацьовує після `git commit` і `git push`.

**Наступний крок:**
Перевірити що хук реально спрацьовує у Влада після його git pull.
