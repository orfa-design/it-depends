## 2026-05-25 — Ідеї для retention і інтеграцій (накидала, не рішення)

- **Daily tokens** — обмежена кількість "токенів" на день що відновлюються (як у Claude). Механіка повернення без streak-тиску — просто "сьогодні є X спроб".
- **Slack інтеграція** — не просто "поділитись посиланням", а щось цікавіше: бот який постить в канал, реакції колег, автоматичний анонс "Оксана зробила свій перший AI плагін".
- **Особистий кабінет як Behance** — збирати посилання на зроблені роботи. Мотивація не просто "зробила" а "маю публічне портфоліо AI-проектів". Колеги можуть переглянути.
- **GitHub інтеграція** — підключити репо прямо в продукті. Можливо: після "Зробила" автоматично пропонує запушити результат.
- **Шлях як escape hatch** — не окремий режим за замовчуванням, а виход коли 3 персоналізовані картки не підійшли. Після третього "Не моє" з'являється "Переглянути всі теми" → повний шлях з рівнями складності: базові промпти → аналіз документів → автоматизація → кодую в Claude Code → агенти. Юзер сам обирає куди стрибнути. Вирішує H4 (не може назвати ідею) і дає відчуття що продукт більший ніж 3 картки.

## 2026-05-25 — Wireframe v1: флоу і зміни

**Було:** рівень → вибір задачі з меню (9 опцій) → промпт
**Стало:** рівень → біль → доступ → свайп-картки (1 за раз) → промпт → "Я спробувала" → completion

**Чому:**
Перша версія відчувалась як "вибери з меню" — юзер сам вибирає, продукт не персоналізує. Core value prop загубився. Повернулась до оригінального брейнштормового флоу з трьома питаннями + свайпом.

---

**Було:** задачі = "що зробити в Claude" (підсумок, аналіз, FAQ)
**Стало:** задачі = артефакт на виході (шаблон для Notion, system prompt, Figma плагін)

**Чому:**
Старі задачі не давали відчуття "наступного рівня" — це те що вона і так могла спитати в Claude. Нові задачі виробляють щось конкретне: файл, інструмент, скрипт. Відповідає wow-моменту "я зробила річ".

---

**Було:** один CTA "Відкрити в Claude →" для всіх
**Стало:** Claude для text-артефактів, Claude Code для code-артефактів (з інструкцією в терміналі)

**Чому:**
Кнопка "Відкрити в Claude Code →" відкривала claude.ai — брехня. Для code-задач реальний шлях це CLI. Зробила чесно: кнопка копіює промпт + показує покрокову інструкцію.

## 2026-05-26 — Маскот і шлях

- **Маскот з мемним потенціалом** — як сова Дуолінго або BitePal. Не просто ілюстрація — персонаж з поведінкою: реагує на дії юзера, "засмучується" якщо вона не повернулась, "радіє" коли завершила крок. Мемний потенціал = органічне поширення без витрат на маркетинг.
- **Шлях-прогрес як в Дуолінго** — не абстрактний прогрес-бар, а візуальний шлях з кроками. Юзер бачить де вона зараз і куди іде далі. Пов'язано з ідеєю escape hatch: шлях відкривається якщо карточки не підійшли.

## 2026-05-27 — Prompt UX: terminal window + кастомізація задачі

**Ідея 1 — Terminal window UI для Claude Code промптів**
Замість plain text + кнопки "Скопіювати" — показувати промпт у вікні що виглядає як термінал (темний фон, monospace, "● ● ●" шапка). Юзер одразу розуміє що це команда для CLI, не просто текст. Референс: Claude Design export modal.

**Ідея 2 — Кастомізація задачі ("Моя задача")**
Структура промпту = незмінна обгортка (хто я, як комунікувати, escape hatch) + змінна частина (сама задача). Показуємо поле "Моя задача" з дефолтним текстом. Юзер може замінити задачу своєю ідеєю — промпт оновлюється live. Якщо очищає → повертається дефолт автоматично.

Чому сильно: закриває H4 (latent ideas) — юзер бачить приклад → розуміє що хоче інше. При цьому не пише промпт з нуля — контекст і супровід вже є.

**Разом:** terminal window показує фінальний промпт live, поле під ним дозволяє замінити задачу. Зміна в полі → оновлення у вікні в реальному часі.

**Статус:** ідея, не в реалізації. Обговорити з Владом перед тим як брати в код.

## 2026-05-31 — Ідеї для гайд-контенту (тіло кроку)

**Ідея 1 — Продаючий опис над промптом**
Перед блоком "МОЯ ЗАДАЧА" додати короткий опис який пояснює/продає цей промпт: що він робить, чому це цінно, можливо фото/скрін аналогічних результатів. Юзер розуміє навіщо йому цей промпт ще до того як його прочитав.

**Ідея 2 — Приклад від автора промпту**
В тілі кроку: секція з прикладом результату — але не від випадкових користувачів, а від того хто додавав промпт. При додаванні кроку автор прикріплює скрін або посилання на свій результат. Це і є "доказ що працює" — автор показує що сам пробував. Природна пре-модерація: автор зацікавлений показати хороший приклад.

**Ідея 3 — Схожі кроки як escape hatch**
Внизу тіла кроку: 2-3 схожих кроки для тих кому поточний не підійшов (занадто складний / простий / нерелевантний). Юзер не повертається на головну — одразу бачить альтернативи і переходить далі. Закриває фрикцію "не моє, але не знаю що моє".

Три ідеї разом утворюють структуру: спершу продаємо (ідея 1) → показуємо доказ (ідея 2) → даємо вихід якщо не те (ідея 3).

**Ідея 5 — Динамічний конструктор промпту через тогли**
В гайді під промптом: необов'язкові тогли що додають контекст. Юзер вмикає тогл → з'являється поле → вписує своє → вставляється в фінальний промпт автоматично. Наприклад: тогл "контекст про аудиторію" → поле "Моя аудиторія" → inject `Аудиторія: {audience}` в промпт. Дефолт — всі тогли вимкнені, базовий промпт вже робочий. Максимум 2-3 тогли на крок. Не беремо в першу збірку — окрема фіча після базової версії.

---

**Ідея 4 — Два типи контенту кроку**
Тип A (простий): одна задача — один промпт. Запускається з одного запиту до AI. Поточні кроки переважно такі.
Тип B (складний / buildFlow): задача потребує кількох продуктів або інструментів послідовно. Наприклад: Figma-плагін + окремий сайт що виводить результати роботи плагіна. Одним запитом не закрити — це багатоетапний процес з залежностями між етапами.

Тип B вже частково є (прапорець `buildFlow` у Влада), але варто зробити це явним для юзера — щоб він розумів ще до початку: "це не 10 хвилин, це кілька сесій". Окремий бейдж, інший вигляд картки, або попередження перед початком.
