Документ для нового репо. Збираємо рішення по мірі їх прийняття.
Технічний стек лишається (Next.js), архітектура і UX — нові.

- **Desktop-first.** Мобільна версія не підтримується. На мобільному пристрої показується повноекранний банер: *"Цей продукт оптимізований для десктопу. Відкрий на комп'ютері для кращого досвіду."*
- Аудиторія: DataArt дизайнери, працюють за ноутбуком.

## Архітектура даних

### Структура `Step`

Один плаский об'єкт. Групи — логічні, не вкладені.

```ts
Step {
  // core — є скрізь
  id
  title
  subtitle       // tagline під заголовком
  category       // 'research' | 'prototyping' | 'code' | 'planning' | 'workflow'
  kind           // 'simple' | 'build'
  effort         // 'quick' | 'iterative' | 'project' — і відображення і порядок на мапі

  // pitch — сторінка кроку, верх
  promise        // "Ти отримаєш / побудуєш..." — конкретна зміна в роботі
  usedWhen       // "Практичне використання: ..."
  tool?            // тільки simple; build — tool в кожній фазі окремо
  authorExample? // { type: 'image' | 'link', url: string, label?: string }

  // guide — сторінка кроку, низ
  taskDefault    // дефолтна задача, юзер може змінити
  promptText?    // simple: один промпт з {task} плейсхолдером
  checkpoint?    // simple: як зрозуміти що вийшло
  stages[]?      // build: { title, tool, action, prompt, checkpoint }
                 // action — рядок-інструкція "що зробити в цій фазі" перед промптом

  // sidebar — сторінка кроку, права колонка
  relatedSteps[] // id кроків → "ТАКОЖ СПРОБУЙ"

  // guide — під основним гайдом
  levelUp[]?     // "⚡ Далі: потужніший шлях" — масив рядків, опційний, будь-який тип кроку
}
```

### Типи кроків

**simple — простий:** одна задача, один промпт, робота в одному чаті.
`guide` = `taskDefault` + `promptText` + `checkpoint`.

**build — збірка:** кілька продуктів або послідовних сесій, вивід фази A = вхід фази B.
`guide` = `taskDefault` + `stages[]`.
Кожна фаза: `title`, `tool`, `action`, `prompt`, `checkpoint`.
`tool` відсутній в pitch — tool є в кожній фазі окремо.
На картці — бейдж "збірка" + кількість фаз.

### Картка

Reusable UI-компонент. Використовується в кількох view (список кроків, галерея тощо).
Показує поля з групи `core`:
- `title`
- `subtitle`
- `category` (тег)
- `kind` (бейдж "збірка" — тільки buildFlow)
- `effort` (бейдж рівня)

Клік → відкриває сторінку кроку.

### Поле `effort` — рівень зусилля і порядок на мапі

| Значення | UI текст | Порядок |
|----------|----------|---------|
| `quick` | "Можна зробити з AI за один підхід" | перші |
| `iterative` | "Може знадобитися кілька ітерацій і підходів" | середина |
| `project` | "Це складний продукт, за 2-3 підходи не вийде закінчити, але і результат того вартуватиме" | кінець |

### Поле `promise` — обіцянка кроку

Правила:
- Починається з "Ти"
- Конкретне дієслово: "отримаєш / побудуєш / протестуєш" — не "зможеш навчитись"
- Без жаргону який потребує розшифровки
- Говорить до досвідченого дизайнера
- Описує зміну в процесі або стосунках з командою

Приклади:
- *"Ти отримаєш специфікацію яку розробник прийме без зустрічі."*
- *"Ти побудуєш пошук по своїй дизайн-системі."*
- *"Ти протестуєш ідею в коді і покажеш розробнику що саме змінити."*

### Поле `usedWhen` — практичне використання

UI лейбл: "Практичне використання:"
Приклад: *"Знадобиться коли хочеш спробувати кілька шрифтів, лаяутів, мобайл проти десктопу"*

## UX — сторінка кроку

### Лейаут

Двоколонковий. Права колонка sticky — не скролиться, завжди видна.

Трьохколонковий. Ліва і права колонки sticky.

```
┌─────────────┬──────────────────────────────┬───────────────────────┐
│  MAP        │  CORE                        │  [взяти в роботу]     │
│  (sticky)   │  title                       │  [я зробила — далі]   │
│  [ крок 1 ✓]│  subtitle · category · kind  │  [✏️]                 │
│  [ крок 2 ▶]│  · effort                    │  [не цікаво / тогл]   │
│  [ крок 3  ]├──────────────────────────────┤                       │
│  [ крок 4  ]│  ПІТЧ                        │  ─────────────────    │
│  [ крок 5  ]│  promise                     │                       │
│  [🔒 скоро ]│  usedWhen                    │  ТАКОЖ СПРОБУЙ        │
│             │  tool · authorExample        │  → крок               │
│             ├──────────────────────────────┤  → крок               │
│             │  ГАЙД                        │                       │
│             │  Моя задача (поле)           │  ─────────────────    │
│             │  промпт / фази               │                       │
│             │  checkpoint                  │                       │
│             │  ⚡ Далі: потужніший шлях    │                       │
└─────────────┴──────────────────────────────┴───────────────────────┘
```

Ліва колонка (Map) прихована на `/gallery`.

### Адаптивна поведінка

- **Перший раз** → Пітч розгорнутий + Гайд нижче
- **Взяла в роботу** → Пітч згортається, Гайд у фокусі
- **Повернулась** → одразу Гайд, Пітч прихований

### Гайд — інлайн (не модалка)

Обидва типи показують гайд прямо на сторінці.
- simple: поле "Моя задача" + промпт + checkpoint
- build: поле "Моя задача" + фази-акордеони з промптами всередині

### Поле "Моя задача" — три джерела

1. **Дефолт** — `taskDefault` з даних кроку, підставляється автоматично
2. **AI-генерація** — кнопка "🎲" біля поля, генерує новий варіант задачі через `/api/generate-task` (stepId → Claude). Клік ще раз — новий варіант.
3. **Вручну** — юзер редагує поле сам

Збережена задача зберігається в `user:{name}` в KV разом зі станом кроку.

### Стани кроку і кнопки

```
[available]
"взяти в роботу" + "я зробила — далі"

       ↓ "взяти в роботу"

[in progress]
"я зробила — далі"
(гайд доступний, поле "моя задача" можна редагувати)

       ↓ "я зробила — далі" → модалка збереження → /step/[id]/done

[done]
бейдж "виконано ✓" + посилання на результат (якщо є)
гайд видний — юзер може змінити задачу і використати знову
"взяти в роботу" — починає нову ітерацію з новим контекстом
```

"спробувати ще раз" відсутня — її роль покриває "взяти в роботу" в done стані.

### Complete flow — модалка + сторінка успіху

Два окремих моменти:

**1. Модалка збереження** (з'являється після "я зробила — далі"):
```
┌─────────────────────────────────┐
│  Готово!                        │
│                                 │
│  URL результату (опційно):      │
│  [________________________]     │
│                                 │
│  [  зберегти  ]        [  ×  ] │
└─────────────────────────────────┘
```
- URL — опційне поле
- "зберегти" → позначає крок `done`, відкриває сторінку успіху
- `×` → закрити без збереження, крок лишається `in progress`

**2. Сторінка успіху** — route: `/step/[id]/done`
Окрема сторінка прив'язана до кроку. Тримається при рефреші.
- Візуальне святкування
- Назва кроку + URL результату (якщо є)
- Share кнопки (WhatsApp, Telegram, LinkedIn)
- Основна кнопка: "на мапу →"
- Нижче: 2-3 картки "ТАКОЖ СПРОБУЙ" з `relatedSteps`

### Кнопки в build-кроці

Кожна фаза має опційну кнопку "закінчити фазу" — для тих хто хоче відмічати прогрес.
Клік на "закінчити фазу" автоматично переводить крок в стан `in progress` якщо він ще `available`.
"я зробила — далі" завжди активна, незалежно від кількості виконаних фаз.

### Повний список кнопок на сторінці кроку

| Кнопка | Де | simple | build |
|--------|----|--------|-------|
| `[🎲]` згенерувати задачу | гайд, біля поля задачі | ✅ | ✅ |
| `[copy]` | гайд, біля промпту | ✅ | ✅ (в кожній фазі) |
| `[+/-]` розкрити фазу | гайд, акордеон | ❌ | ✅ |
| "закінчити фазу" | гайд, кожна фаза | ❌ | ✅ опційна |
| "взяти в роботу" | sidebar (sticky) | ✅ | ✅ |
| "я зробила — далі" | sidebar (sticky) | ✅ | ✅ завжди активна |
| ✏️ редагувати крок | sidebar | ✅ | ✅ |
| "не цікаво" (тогл) | sidebar | ✅ | ✅ |
| поле URL | модалка збереження | ✅ опційно | ✅ опційно |
| "зберегти" | модалка збереження | ✅ | ✅ |
| share кнопки | сторінка успіху | ✅ | ✅ |
| "на мапу →" | сторінка успіху | ✅ | ✅ |

## Калібровка — онбординг

### Мета
Познайомити юзера з продуктом через реальні кейси, не абстрактні питання про рівень. Результат: юзер потрапляє на галерею з персональними рекомендаціями нагорі.

### Механіка
Story-картки: кожна картка — реальний кейс. Юзер обирає одну з трьох реакцій.
Реакції зберігаються → продукт розуміє що цікаво.

**Три реакції:**
- "Круто, ніколи б не подумала, що AI таке вміє" (`wow`) → наступна картка з тієї ж або суміжної категорії
- "Чула про таке, але не пробувала, цікаво" (`heard`) → інша категорія, але не далеко
- "Не цікаво" (`skip`) → зовсім інша категорія

**Адаптивна послідовність:** картка №2 залежить від відповіді на №1, №3 від відповіді на №2, і так далі. Це не лінійний список, а дерево рішень де кожна відповідь звужує і персоналізує наступний вибір.

Технічно: картки зберігаються в KV під ключем `calibration`. Fallback — `lib/calibration.ts`. Редагуються через ✏️ як і кроки.

Структура картки:
```ts
CalibrationCard {
  id
  name      // імʼя персонажа ("Аня")
  role      // роль і контекст ("Product designer · fintech · 4 роки")
  pain      // біль — що не так було
  move      // що зробила з AI
  out       // результат
  effort    // 'quick' | 'iterative' | 'project' — замість конкретного часу
  category  // яку категорію кроків відображає ('research' | 'prototyping' | 'code' | 'planning' | 'workflow')
  next: { wow: cardId, heard: cardId, skip: cardId }  // дерево переходів
}
```

### Флоу
- Показується **один раз** при першому відвідуванні (`/calibrate` або вбудовано в головну).
- Кнопка "пропустити" завжди доступна → одразу на галерею без рекомендацій.
- Після завершення → redirect на `/gallery` з рекомендованими картками нагорі.

## Gallery і Map — перегляд кроків

### Gallery (`/gallery`) — основна сторінка

Список карток усіх кроків + фільтри. Юзер сам обирає що брати, жорсткого порядку немає.

**Фільтри:**
- `effort`: quick / iterative / project
- `category`: research / prototyping / code / planning / workflow
- `kind`: simple / build (бейдж "збірка")

Персональні рекомендації (після калібровки) — окрема горизонтальна секція нагорі "Для тебе".

### Map (`/map`) — рекомендований шлях

Gallery / Map — основне верхньорівневе перемикання режимів перегляду (toggle в хедері).

Map — persistent ліва колонка: маршрут завжди видний як ліва sticky колонка включно зі сторінкою кроку. Юзер бачить де він в маршруті не виходячи з кроку. Прихована тільки на `/gallery`.



Після калібровки продукт збирає персональну послідовність 5–7 кроків — "твій старт". Це не жорстка черга: юзер може відхилятись, пропускати, повертатись. Але є відчуття маршруту і точка входу.

```
[ крок 1 ] → [ крок 2 ] → [ крок 3 ] → [ крок 4 ] → [ крок 5 ]
  виконано    в роботі      далі          далі          далі
```

Кожен крок — картка зі станом: виконано / в роботі / далі. Всі картки одразу видні, без accordion або lazy load.
Кроки підібрані на основі реакцій з калібровки.
Якщо калібровку пропустили — показується дефолтний шлях (quick-кроки по всіх категоріях).

Кнопка "переглянути всі" → Gallery.

### Map lifecycle

**Приховати крок з маршруту — кнопка "не цікаво":**
Тогл у правій колонці сторінки кроку. Перший клік → крок позначається як "не цікаво": зникає з маршруту і з секції "Для тебе" в галереї. Другий клік → скасовує, крок повертається. Сам крок завжди доступний в галереї напряму.

**Перебудувати маршрут:**
В MVP недоступно. На мапі показується банер: *"Скоро тут можна буде перебудувати маршрут — ця функція в розробці."*

**Кінець маршруту:**
Після останнього кроку завжди показується картка із замочком: *"Скоро тут з'являться нові кроки — ми їх зараз додаємо."* Не залежить від того, чи виконані кроки.

**Нова калібровка:**
Технічно перераховує маршрут, але в MVP повторна калібровка недоступна.

### Різниця між view

| | Gallery | Map |
|-|---------|-----|
| Порядок | довільний (фільтри) | персональна послідовність |
| Вигляд | сітка всіх карток | 5–7 кроків з прогресом |
| Пошук | так (фільтри) | ні |
| Персоналізація | рекомендації нагорі | весь вміст |

## Профіль і хедер

### Профіль в хедері

Окремої сторінки профілю немає — все що потрібно показується в хедері сайту.

**Хедер містить:**
- Логотип / назва → повертає на останній активний view (gallery або map), запам'ятовує стан
- Toggle: Gallery / Map
- Лічильник активних задач (число) → клік веде на `/progress`
- Ім'я поточного юзера (з localStorage) — клік → `/login` щоб змінити ім'я
- "+ Додати крок" → відкриває 2-крокову модалку створення кроку
- "✏️ Копі" → відкриває мікрокопі drawer для редагування статичних текстів
- "Почати все з початку" — скидає весь прогрес до дефолтного стану; технічна кнопка для тестування, не для юзерів

### Сторінка `/login` — вхід по імені

Одне поле: "Як тебе звати?" + кнопка "Увійти".
- Ім'я зберігається в localStorage як поточна сесія
- Якщо `user:{name}` вже є в KV — підхоплює існуючий прогрес
- Якщо нове ім'я — створює порожній запис, редирект на `/calibrate`
- Якщо вже є ім'я в localStorage — `/login` показує його з опцією змінити

### Сторінка `/progress` — активні задачі

Список карток кроків зі статусом `in progress`.
Лейаут ідентичний Gallery, але без фільтрів.
Клік на картку → сторінка кроку зі збереженою задачею і фокусом на гайді.
Порожній стан: "Ти ще не взяла жодного кроку в роботу" + кнопка на галерею.

## CMS — редагування контенту

### База даних

Vercel KV (Redis). Чотири ключі:
- `steps` — масив всіх кроків
- `calibration` — масив карток калібровки з деревом переходів
- `copy` — об'єкт з мікрокопі, згрупований по сторінках
- `user:{name}` — прогрес юзера: стани кроків, збережені задачі, URL результатів, реакції калібровки, позначки "не цікаво"

Поточне ім'я сесії зберігається в localStorage. Прогрес — виключно в KV.

### Редагування кроку

Кнопка ✏️ на сторінці кроку — відкриває форму редагування без глобального режиму.
Форма з секціями: core / pitch / guide / sidebar.
Для build — динамічний список фаз.
Зберігає в KV → зміна видна одразу для всіх.

### Додати новий крок

Кнопка "+ Додати крок" в хедері — завжди видима (як і ✏️ на кроках).
Відкриває модалку з 2 кроками:

**Крок 1 — core + pitch:**
- `title` (обов'язкове)
- `subtitle` (обов'язкове)
- `category` — dropdown (обов'язкове)
- `kind` — radio: simple / build (обов'язкове, визначає крок 2)
- `effort` — radio: quick / iterative / project (обов'язкове)
- `promise` (обов'язкове)
- `usedWhen` (обов'язкове)

**Крок 2 — guide** (залежить від `kind`):
- simple → `tool` + `taskDefault` + `promptText` + `checkpoint`
- build → `taskDefault` + динамічний список фаз (`title`, `tool`, `action`, `prompt`, `checkpoint`)

Опційні поля (`authorExample`, `relatedSteps`, `processNotes`) — заповнюються потім через ✏️ на сторінці кроку.
`id` генерується автоматично зі slug від `title`.
Зберігає в KV → крок одразу з'являється в галереї.

### Мікрокопі drawer

Push drawer, відкривається кнопкою "✏️ Копі" в хедері.
Всі статичні тексти згруповані по сторінках.
Зберігає в `copy` в KV.

Структура об'єкту `copy`:

## Технічний стек

- Next.js (App Router)
- Vercel KV для даних
- `lib/kv.ts` — всі читання/записи
- `lib/copy.ts` — дефолтні тексти (fallback якщо KV порожній)
- `lib/data.ts` — дефолтні кроки (fallback якщо KV порожній)
- `lib/calibration.ts` — дефолтні картки калібровки (fallback якщо KV порожній)

### Маршрути

| Route | Опис |
|-------|------|
| `/` | Редирект → `/login` (якщо немає імені) або `/calibrate` (перший раз) або `/gallery` |
| `/login` | Одне поле "Як тебе звати?" — встановлює сесію, редирект на `/calibrate` або `/gallery` |
| `/calibrate` | Онбординг — story-картки з реакціями |
| `/gallery` | Всі кроки, фільтри, рекомендації нагорі |
| `/map` | Персональний маршрут 5–7 кроків |
| `/step/[id]` | Сторінка кроку |
| `/step/[id]/done` | Сторінка успіху після завершення кроку |
| `/progress` | Активні задачі (in progress) |
| `/api/generate-task` | API: генерація варіанту задачі через Claude (POST, stepId) |
